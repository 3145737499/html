- 后端已运行（9090 监听中）→ 脚本自动跳过，不会重复启动

- `node_modules` / `target` 每次开机被删除 → 脚本**已内置**自动 `npm install` 和 Maven 重新编译，无需人工干预

## 已踩过的坑（别再犯）

1. **bat 脚本必须 GBK 编码 + CRLF 换行**（chcp 936）。Write 工具写出的是 UTF-8 + LF，正确做法：`iconv -f UTF-8 -t GBK 临时文件 | sed 's/$/\r/' > 目标.bat`。LF-only 的 bat 会被 cmd 拆行错乱执行（如报 `'odules' 不是内部或外部命令`）。
2. **严禁对本项目 bat 用 `sed -i`**：本机 git-bash 的 sed -i 读文件时会把 `\r` 吃掉（文本模式读、二进制写），CRLF 直接变 LF 导致脚本报废。要改 bat 就整体重新生成。
3. **mysql 命令行导入含中文的 SQL 必须加 `--default-character-set=utf8mb4`**，否则报 `Data too long for column`。
4. **环境变量 `SERVER__PORT` / `SERVER__HOST` 会污染 Spring Boot 配置**（宽松绑定当成 server.port），启动前必须 `set SERVER__PORT=` 清空——start-backend.bat 已处理。
5. 后端图形验证码是 AWT 画的（AuthServiceImpl.drawCaptcha），内存缓存 5 分钟一次性；**不是邮箱验证码**，`spring.mail.*` 留空不影响任何功能。
6. Vite dev server 的 `wait --load networkidle` 可能永不返回（SPA 长连接），自动化时别等 networkidle。
7. 本机 PowerShell 工具查询服务/进程经常返回空输出，不代表不存在；验证服务用 curl.exe 写结果到文件再读，或直接 netstat。
8. **系统 Node 是 20.11.0，Vite 7 跑不起来**（`crypto.hash is not a function`，Vite 7 要求 Node 20.19+）。2026-10-12 已把 package.json 锁到 vite ^6.3.5 + @vitejs/plugin-vue ^5.2.4，别升级回 7。
9. **Vite 只监听 IPv6 `[::1]:5173`**（host 默认 localhost）：curl `127.0.0.1:5173` 会 000，用 `http://[::1]:5173/` 或 localhost。浏览器访问正常。后端 9090 是 IPv4+IPv6 双栈，无此问题。
10. bat 里等延时用 `ping -n 3 127.0.0.1 >nul`，别用 `timeout /t`（stdin 被重定时它会报"不支持输入重新定向"并立即失败）。
11. **git-bash 里 `cmd //c xxx.bat` 跑不起来**（只打 banner 不执行，疑似参数转换问题）；WorkBuddy 会话中重启后端的正确姿势：先 `Stop-Process -Id <pid> -Force`（PowerShell）杀 9090，再 `cd springBootTest && env -u SERVER__PORT -u SERVER__HOST ./mvnw.cmd spring-boot:run > start-log.txt 2>&1` 后台跑（SERVER__PORT 在该会话环境里确实存在，必须 -u 清掉）。
12. git-bash 里 `taskkill //F //PID n` 报"无效参数"，杀进程用 PowerShell 的 `Stop-Process`。
